# Rules glossary

[D&D Beyond's Rules Glossary](https://www.dndbeyond.com/sources/dnd/br-2024/rules-glossary) (Free Rules 2024) is one long page: every entry is an `<h3>`, its sub-sections are `<h4>`s, and some entry names carry a tag in brackets (`Attack [Action]`, `Prone [Condition]`). [scrape_rules_glossary.py](scrape_rules_glossary.py) turns it into:

```
SourceTexts/RulesGlossary/
  index.md                     sections table, the glossary's own conventions + abbreviations, A-Z list
  Terminology/index.md         every folder: description, sub-sections, entries with their first sentence
  Terminology/Creature.md      one file per entry: title, breadcrumb, link back to D&D Beyond, full text
  D20-Tests/  Combat/{Actions,Attacks,Stats,Damage-and-Healing}/  Conditions/  Areas-of-Effect/
  Spells-and-Magic/  Movement/  Vision-and-Senses/  Exploration/Hazards/  Social-Interaction/
```

File names drop the tag (`Combat/Actions/Attack.md`, `Conditions/Prone.md`), and the folder already says it. Links between entries are relative (`../../Conditions/Grappled.md`, `#object-armor-class` for an `<h4>`), so the tree works in VS Code and on GitHub. Links to other D&D Beyond pages stay absolute. Tables become Markdown tables, art is dropped, and curly quotes become straight ones so `grep "can't"` works.

## Looking something up

Don't run anything; read or grep the tree:

```bash
grep -rl "Difficult Terrain" SourceTexts/RulesGlossary/     # which entries mention it
cat SourceTexts/RulesGlossary/Conditions/Grappled.md
```

If the folder is missing, generate it first.

## Generate or refresh (needs network, about 2 s)

```bash
python .claude/skills/rules-glossary/scrape_rules_glossary.py                    # fetch and write SourceTexts/RulesGlossary/
python .claude/skills/rules-glossary/scrape_rules_glossary.py --html saved.html  # parse a saved copy of the page instead
python .claude/skills/rules-glossary/scrape_rules_glossary.py --out <dir>        # write somewhere else (e.g. the scratchpad)
```

It prints the entry count per folder and every file it created or deleted. Re-runs are safe: unchanged files are not rewritten, and a generated file whose entry is gone (removed, renamed or moved) is deleted. Only files whose first line is the `<!-- Generated by ... -->` marker are ever deleted or overwritten. A hand-written file in the tree is left alone, and the script refuses to overwrite one. Never hand-edit a generated file; change the script or `categories.json` and re-run.

Exit status is 1 when some entry has no folder (see below), else 0.

## Which folder an entry goes to

[categories.json](categories.json) decides, in this order:

1. **`tags`**: an entry with a bracket tag goes to that tag's folder (`[Action]` → `Combat/Actions`, `[Condition]` → `Conditions`, `[Area of Effect]` → `Areas-of-Effect`, `[Hazard]` → `Exploration/Hazards`, `[Attitude]` → `Social-Interaction`). New tagged entries need no edit.
2. **`folders.<folder>.entries`**: untagged entries, listed by name (the heading without its tag).
3. An entry named like a tag (`Action`, `Condition`, `Hazard`, ...) goes with its family.
4. Anything else goes to `Uncategorized/` and the script exits 1, printing the names. Add each one to the right folder's `entries` and re-run. If it also says *categories.json lists names the page no longer has*, that is usually the same entry under its old name, so remove the old name.

`folders` order is the order of the sections table, and each `description` is that folder's intro line. A new folder is just a new key (`"Combat/Turns": {...}`): the parent's `index.md` lists it as a sub-section. Moving an entry is a one-line change plus a re-run, which deletes the old file.

## When the page layout changes

The script exits with a message if it finds no `.p-article-content` block or no `<h3>` entries. For anything subtler (a new block type that renders empty, a table that looks wrong), save the page (`curl -sL -A "Mozilla/5.0 ..." -o <scratchpad>/glossary.html <url>`), run with `--html` and `--out` into the scratchpad, and compare with the current tree. Block types are handled in `Renderer.blocks`.
